# Contributing to OpenMotion

Thank you for your interest in contributing to OpenMotion!

OpenMotion is intended to be a collaborative open-source project. Contributions from students, researchers, educators, engineers, developers, and hobbyists are welcome. Contributions can include software development, hardware support, documentation, testing, data analysis, and ideas for improving the project.

## Ways to Contribute

There are many ways to contribute to OpenMotion, including:

* Reporting bugs or unexpected behavior
* Suggesting new features
* Improving documentation
* Adding examples and tutorials
* Supporting additional IMU sensors or microcontrollers
* Improving data visualization
* Developing data-processing methods
* Creating or improving tests
* Developing machine-learning functionality
* Reviewing and providing feedback on proposed changes

Contributions do not need to involve writing code. Documentation, testing, issue reports, and constructive feedback are also valuable contributions.

## Reporting an Issue

If you find a bug or problem with OpenMotion, please create a GitHub Issue.

When reporting an issue, provide as much information as possible, including:

* A clear description of the problem
* The hardware and software being used
* Steps to reproduce the problem
* Any relevant error messages
* Expected behavior
* Actual behavior
* Screenshots or example data when appropriate

Before creating a new issue, please check the existing issues to see whether the problem has already been reported.

## Suggesting a Feature

Feature suggestions are welcome.

When proposing a new feature, describe:

* What the feature would do
* Why it would be useful
* Who would benefit from it
* How it could fit into the existing OpenMotion system

Feature requests should focus on improving the project for its broader community rather than only addressing an individual user's needs.

## Pull Requests

If you would like to contribute code or documentation:

1. Fork the OpenMotion repository.
2. Create a new branch for your changes.
3. Make and test your changes.
4. Update documentation when necessary.
5. Commit your changes with a clear commit message.
6. Submit a pull request to the OpenMotion repository.
7. Respond to feedback from the project maintainer.

Pull requests should describe what was changed and why the change is useful to OpenMotion.

## Development Guidelines

Contributors should aim to:

* Keep changes focused on a specific issue or feature.
* Use clear and descriptive names for files, functions, variables, and other project components.
* Follow the existing coding conventions.
* Test changes before submitting a pull request.
* Update documentation when functionality changes.
* Avoid including passwords, private credentials, or other sensitive information in commits.

## New Contributors

OpenMotion is intended to be welcoming to contributors with different levels of experience.

If you are new to open-source development, documentation improvements, testing, issue reporting, and small bug fixes are good ways to get started.

If you are unsure how to contribute, open an issue describing your idea or question before beginning a large change.

## Questions

If you have a question about contributing to OpenMotion, please open a GitHub Issue or Discussion so that the question and answer can benefit other members of the community.
